# 3D 渲染补齐：半透明、聚光灯、点光源和聚光灯阴影、级联阴影、动画淡入淡出、变形

> 前置：3D 补充（[3d-more.md](3d-more.md)）、骨骼动画（[animation.md](animation.md)）、3D 粒子（[particles3d.md](particles3d.md)）。

## 目标

现在 3D 这边有几块明显的短板：
- glTF 里半透明（`BLEND`）的材质按不透明画，玻璃、水面、幽灵都是实心的。
- 灯只有方向光和点光源，手电筒、路灯、舞台灯这种一束一束的光做不出来。
- 影子只有一盏方向光能投，而且一张阴影图框住所有物体：场景一大，影子边缘就是一格一格的。
- 换动画是硬切，走路一下子变成跑步，人会跳一下。
- glTF 的变形（morph target，表情、挤压、呼吸）读不进来。

**验收标准**：
- 半透明：材质 `blend` 的模型能透出后面的东西，几个半透明的叠在一起时由远到近正确混合；不透明的东西照常挡住半透明的。
- 聚光灯：有位置、方向、内外锥角，锥外不亮、内外锥之间平滑过渡；能投影子。
- 点光源能投影子（六个方向）。
- 级联阴影：方向光可以把相机前面 `distance` 以内切成 2–4 段，各画一张阴影图，近处的影子细。
- 动画：`Animator::play(clip, fade)` 在 `fade` 秒里从旧动画过渡到新动画。
- 变形：glTF 的 morph target 读进来，默认权重和 `weights` 动画通道都生效；和蒙皮能同时用。

## 做法

### 半透明（`Material.blend`）

- `Material` 加 `blend: bool`。glTF 的 `alphaMode: BLEND` 读成 `blend = true`（之前按不透明画并警告）。
- 画法：
  - 不透明的先画，按管线、贴图排；半透明的排在后面，按包围盒中心沿相机前方向到相机的线性距离**由远到近**画（透视、正交都一样；不用 z / w，中心在相机背后时它会反号）。
  - 半透明管线：颜色按 `SrcAlpha, OneMinusSrcAlpha` 混合，深度照常比较、不写深度（后面的半透明不会被前面的挡掉）。
  - 片元输出贴图和 `base_color` 乘出来的 alpha；不透明的照旧输出 1。
- 管线从 6 条变 12 条：剔除方式 × 蒙皮 × 半透明。
- 半透明的不投影子（玻璃投一整块黑影不对）。
- 半透明的网格和方片、带子（粒子）之间不互相排序：方片总是画在所有网格后面。
- 半透明的不写深度，混排时也不和 2D 精灵排序：z ≥ 0 的精灵总在 3D 后面画，会盖在半透明网格上。

### 聚光灯（`SpotLight`）

```rust
pub struct SpotLight {
    pub color: Vec3,
    pub intensity: f32,
    pub range: f32,
    /// 半角（弧度）：内锥里是全亮，外锥外是黑，中间平滑过渡。
    pub inner_angle: f32,
    pub outer_angle: f32,
    pub shadows: bool,
}
```

- 位置和朝向都取同一实体的 `Transform3d`，照向 `rotation × -Z`（和相机一样）。
- 衰减和点光源一样（按距离平方、到 `range` 平滑降到 0），再乘锥的系数 `smoothstep(cos 外, cos 内, cos θ)`。
- 最多 4 盏（`MAX_SPOT_LIGHTS`），多出来的忽略并警告一次（和其他灯一起）。
- 外锥角限制在 (0, 89°]，内锥不超过外锥。

### 阴影

`Shadows` 多了几项：

```rust
pub struct Shadows {
    pub size: u32,          // 方向光阴影图边长，默认 2048
    pub cascades: u32,      // 1–4，默认 1
    pub distance: f32,      // 级联覆盖到相机前多远，默认 50
    pub local_size: u32,    // 聚光灯、点光源阴影图边长，默认 512
}
```

- **方向光**：
  - `cascades = 1` 时和以前一样：一张图框住所有物体。
  - 正交相机按 1 段处理（只画一张、着色器不分段）：正交的每段横截面都是整屏，近处不会更细，分段没用。
  - `cascades > 1` 时把相机视锥从 `near` 到 `min(far, distance)` 切成几段，分段点用对数和均匀各一半（远处一段更长）。每段：
    - 算出这一段视锥的 8 个角，用外接球的直径再加两格做正方形的边长（相机转动时尺寸不变，影子不抖）。
    - 中心对齐到阴影图的像素格：往负方向最多挪一格，所以每边多留一格，半边长是 `半径 + 一格`，整个外接球都在图里。
    - 深度方向扩到所有物体的包围盒，段外但挡在光路上的东西也投影子。
  - 着色器按片元在相机前方的距离挑段；超过最后一段的没有影子。
- **聚光灯**：第一盏开了 `shadows` 的，从灯的位置按外锥角透视画一张图，近平面是 `range` 的 1%。
- **点光源**：第一盏开了 `shadows` 的，朝 ±X、±Y、±Z 各画一张 90° 的透视图。着色器先按法线往外推，再按推出去之后的点相对灯的方向最大的那一轴挑面（挑面和采样用同一个点，面和面交界的对角线上不漏光）。
- 阴影图：
  - 方向光一张 `size × size × cascades` 的深度数组。
  - 聚光灯和点光源合用一张 `local_size × local_size × 7` 的深度数组：第 0 层是聚光灯，1–6 层是点光源的六面。
- 每层的光矩阵都放进 `Globals`（4 + 1 + 6 个）。阴影 pass 每层一遍，只画包围盒和这一层视野相交的。
- 采样都是 3×3 PCF。法线方向往外推的量按这一层一个像素在世界里多大算：透视的按到灯的距离放大。

### 动画淡入淡出（`Animator::play`）

```rust
impl Animator {
    /// 换成 `clip`，`fade` 秒里从现在的动画过渡过去；`fade` 不是有限的正数时硬切。同名时什么也不做。
    pub fn play(&mut self, clip: impl Into<String>, fade: f32);
}
```

- `fade` 不是有限的正数（0、负数、NaN、无穷大）时硬切。
- `Animator` 多一个 `fade: Option<Fade>`，记着旧动画的名字、时间、速度、循环、已经过了多久、一共多久。
- 每帧旧动画也照常往前走。两边各采样一份本地变换，按 `过了多久 / 一共多久` 混：位置、缩放线性，旋转 slerp，变形权重线性。到时间以后丢掉旧的。
- 旧动画的名字找不到时直接按新动画画。
- 淡入淡出途中再 `play`：
  - 换回正在淡出的那个：两边对调，它接着自己的时间、速度、循环走；已经混了的比例反过来（新进度 = 1 − 旧进度），再按新的 `fade` 换成 `elapsed`。画面不跳。
  - 换成第三个：新动画占不到一半时，还在淡出的那个更重，从它淡出；不然从原来的新动画淡出。另一边丢掉（这一帧会跳一点）。
- 只有时间、淡出进度真变了才改 `Animator`：暂停（帧间隔 0）或速度 0 时不把它标成改过。

### 变形（morph target）

- `Mesh` 加 `targets: Vec<MorphTarget>`，每个目标有每个顶点的位置差和法线差（法线差可以为空）。最多 8 个（`MAX_MORPH_TARGETS`），多的丢掉并警告。
- glTF：
  - 读图元的 `targets`（POSITION、NORMAL）。
  - 读网格或节点的默认 `weights`，放到 `Part.weights`。
  - 动画的 `weights` 通道按每 4 个权重拆成一个通道：`Property::Weights(段)`。原来的采样代码不用改。
- `Pose` 多一份每个节点的权重；没在播动画时用 `Part.weights`。直接用 `Mesh3d` 的实体可以加 `MorphWeights(Vec<f32>)` 组件。
- GPU：
  - 所有网格的位置差、法线差放进一个只增不减的 storage buffer，和关节矩阵在同一个 bind group。不留 CPU 副本：放不下时建一个两倍大的，在 GPU 上把旧数据拷过去，再重建 bind group。
  - 总量超过设备一次能绑定的 storage buffer 大小时，warn 一次，这个网格不变形（目标数按 0）。
  - `Draw` 多了 `morph`（起点、目标数、顶点数）和 8 个权重。
  - 顶点着色器按 `vertex_index` 先加变形，再做蒙皮；阴影 pass 也一样。
- 包围盒（拟合阴影、排序用）：每个顶点按各目标位置差的绝对值之和（Σ|d|，分量各自算）往两边扩。glTF 的权重可以是负的，几个目标也能同时加满，只并上每个目标权重 1 的位置不够。

### 场景和 TSX

- `LightNode` 的 `kind` 多一个 `"spot"`：
  - 位置用 `x`、`y`、`z`，朝向用 `direction`。
  - 锥角用 `angle`（外锥，度）和 `innerAngle`（度，默认外锥的 80%）。
  - `shadows` 对聚光灯和点光源也生效。
- 相机节点 `camera3d` 多 `shadowCascades`、`shadowDistance`。
- `ModelNode.animation` 多 `fade`（秒）：换 `clip` 时按它过渡。
- 材质透明不用场景层管：glTF 写了 `BLEND` 就是半透明。

### 平台跳跃

- 第一关多一盏照向箱子堆的聚光灯，开影子。
- 一只半透明的幽灵果冻：半透明材质，带一个挤压的 morph 动画（`squish`），玩家靠近时从 `idle` 淡入 `squish`。放在角色和其他 z ≥ 0 的精灵后面（`z = 0`）：半透明不写深度，后画的精灵会盖上去，放在后面盖上去才对。
- 太阳的影子用默认的一段：平台跳跃是 `match2d` 的正交相机，级联没用。
- `tools/gen_glb.py` 生成 `jelly.glb`。

## 不做

- 半透明网格和粒子方片之间排序；半透明网格和混排的 2D 精灵之间排序（z ≥ 0 的精灵总在后面画）；同一网格里自己的三角形排序（凹的半透明模型自己挡自己会有错）；顺序无关的透明（OIT）。
- 半透明物体投出彩色或半透的影子；透明度测试（`MASK`）的模型投的影子也不按贴图挖洞（和以前一样）。
- 多于一盏聚光灯、一盏点光源投影子；软阴影（PCSS）；级联之间渐变过渡。
- 动画叠加（additive）、分层（上半身一个、下半身一个）、混合树、动画事件。
- 变形的切线；超过 8 个目标。

## 验收

- `nge-render3d` 单元测试：
  - 半透明排序（由远到近，不透明的在前）；排序深度是沿相机前方向的线性距离；透视相机下中心在相机背后的半透明物体比前面的近，排在后面画；glTF `BLEND` 读成 `blend`。
  - 聚光灯打包、锥角限制、超上限丢弃。
  - 级联分段点单调、最后一段到 `distance`；每段的矩阵框住这段视锥；对齐像素格以后相机平移一点矩阵只按整格变；对齐后整个外接球（含被往负方向挪了快一整格的情况）都在图里。
  - 正交相机设了 `cascades = 3` 也只算一段、没有远端。
  - 聚光灯和点光源六面的矩阵：灯前面的点投在图里、背后的不在；六面合起来覆盖所有方向。
  - `Animator::play`：淡入一半时位置在中间、旋转 slerp；到时间丢掉旧的；同名不重来；`fade` 是 0、负数、NaN、无穷大时硬切；淡到一半换回旧的，下一帧姿势连续、旧动画的时间接着走；反向时进度按新的 `fade` 换算；换第三个时从权重大的一边淡出。
  - 速度 0 没有淡出、淡出中但暂停时，`Animator` 不被标成改过（`Changed<Animator>` 查询数到 0）；真在淡出时照常标记。
  - 变形：glTF 目标、默认权重、`weights` 通道拆段；超过 8 个丢掉；包围盒按 Σ|d| 往两边扩，几个目标同时加满、权重是负的都在盒子里；变形缓冲按两倍扩容、不超过绑定上限，超过时放不下。
- 离屏渲染测试（在 GPU 上跑，没有 GPU 时跳过）：
  - 半透明的红方块盖在蓝方块前面，像素是混出来的紫；两块半透明换了画的顺序（实体创建顺序）像素一样。
  - 聚光灯锥里亮、锥外暗；挡板后面的地面在影子里。
  - 点光源上下左右各一块挡板，四个方向的地面都有影子；挡板的影子落在灯斜下方 45° 的对角线附近（-Y 面和 +X 面交界），那里的地面也在影子里。
  - 级联：远近两处的投影物都有影子，`distance` 外的没有。
  - 运行中改 `Shadows.size`、`local_size` 并挪动投影物：方向光和聚光灯的影子都跟到新位置（主 pass 换用了新的阴影图）。
  - 变形：权重 0 和 1 时顶点在两处；同时蒙皮的也对；先上传一个小的变形网格，下一帧再上传一个大的让缓冲扩容，两个都按权重变形。
- 场景层：`kind: "spot"` 的字段（`direction` 正对 +Z 时也转得过去）、`shadowCascades`、`fade` 换动画时走 `play`。
- 平台跳跃：果冻的 z 在角色后面、不小于 0。
- `nsh test`、`nsh check`、iOS 编译通过。
- 变异验证：上面每一处修复临时改回旧逻辑，对应的测试都会挂。下面几处改了测试抓不到，但和原来等价：
  - 级联的 `size.max(3)` 去掉 `max`：`size` 已经限制在 [64, 4096]，不会小于 3。
  - 淡出时只比较 `elapsed` 有没有变（不比较旧动画的时间）：帧间隔是 0 时旧动画的时间本来就不变（它总是上一帧 `advance` 出来的，已经在 [0, 时长] 里）；帧间隔不是 0 时 `elapsed` 一定变。
  - `Fade` 进度去掉 0–1 的限制：引擎自己写的 `elapsed` 总在 [0, `duration`] 里，只有手动改坏字段时才用得上。
  - 变形缓冲放不下时的分支（warn、不变形）在 GPU 上没测：要超过设备的绑定上限（通常 128 MB 以上）才走得到；判断放不放得下的 `capacity_for` 有单元测试。
- 还没手测。

## 修过的问题

- 半透明排序用的是投影后的 z / w：物体中心在相机背后时 w 是负的，z / w 反号，近的被当成最远的先画。改成按中心沿相机前方向到相机的距离排，透视和正交都适用。
- 淡入淡出途中再 `play` 时，新动画总是从头开始、旧的从当前动画开始淡出：换回正在淡出的那个时画面会跳，它的时间也归零。改成两边对调、恢复它的时间、速度、循环，进度反过来按新的 `fade` 换算；换第三个时从权重大的一边淡出。
- `fade` 是无穷大时淡出永远不结束：改成不是有限的正数就硬切。
- 淡出期间每帧都拿 `Animator` 的可变引用，暂停时也被标成改过：改成只有时间或进度真变了才写。
- 点光源阴影按往外推之前的方向挑面、按推出去之后的点采样：面和面交界的对角线附近，采样点落到挑中的面外面，算成照亮，影子里漏出一条亮线。改成按推出去之后的点挑面。
- 级联的中心往负方向对齐像素格后，正方向少了将近一格，外接球的边可能出图：半边长改成 `半径 + 一格`（边长正好 `size` 格）。
- 正交相机下也照样分级联，但每段横截面都是整屏，近处不更细，白白多画几遍：正交相机按 1 段处理。平台跳跃（正交相机）的太阳去掉了级联设置。
- 平台跳跃的果冻放在角色前面（z = 30），但半透明不写深度，后画的 z ≥ 0 精灵整个盖在它上面，前后关系反了：挪到角色和其他精灵后面（z = 0）。
- 变形的包围盒只并上每个目标单独加满时的位置：几个目标同时加满、权重是负的时顶点会跑出包围盒（阴影拟合、半透明排序、阴影 pass 的剔除都可能出错）。改成每个顶点按 Σ|d| 往两边扩。
- 变形缓冲为了扩容时整份重写，在 CPU 上留着所有网格变形数据的副本：改成扩容时在 GPU 上把旧数据拷到新缓冲；超过设备一次能绑定的大小时 warn 一次、这个网格不变形，不再建一个绑定不了的缓冲。
- 每帧收集灯光、部件和方向光的级联时都新建列表：改成存在渲染器和阴影资源里，清空后复用；收集的代码挪到 `collect.rs`。
