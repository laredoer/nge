# 关卡编辑器

> 前置：TSX 场景（[m3-tsx.md](m3-tsx.md)）、平台跳跃（[platformer.md](platformer.md)）、关卡切换（[levels.md](levels.md)）、Tiled 地图导入（[tiled.md](tiled.md)）。

## 目标

平台跳跃的关卡现在要么写在 `levels.ts` 的代码里，要么用 Tiled 画。两种都看不到游戏里的样子：Tiled 不认识移动平台、3D 箱子、灯，摆完要跑起游戏才知道对不对。这一项用 nge 自己做一个关卡编辑器：中间的画布就是游戏视图（引擎自己的渲染，所见即所得），摆好就能按一下直接试玩。

**验收标准**：
- `examples/editor` 是一个 nsh 应用：左边场景树、中间画布（游戏视图）、右边属性面板、底下物件库和瓦片调色板、顶上工具栏。
- 关卡文件：一个带版本号的 JSON 格式（瓦片层 + 实体列表，实体有类型、位置、尺寸、属性；灯、3D 模型也是实体）；读入时校验，坏数据报出哪一处不对、不崩；保存时格式化（瓦片一行一行、实体一个一行）。
- 编辑：平移 / 缩放视图，点选、框选、拖动移动、网格吸附，从物件库放新实体，改名、删除、复制、排序，属性面板改位置、尺寸和类型专属属性（数值校验），瓦片刷画 / 擦，撤销 / 重做，快捷键。
- 文件：新建、打开、保存、另存为；有未保存的修改时标题上有标记，新建 / 打开前问要不要保存。
- 试玩：按钮或 ⌘R / F5 用正在编辑的关卡直接跑平台跳跃，Esc 回到编辑，编辑状态（关卡、选中、视图、撤销历史）都还在。
- 平台跳跃能直接加载这种关卡文件：第二关「石阶」从 `levels.ts` 的代码导出成关卡文件，游戏读文件；原来的关卡和测试不坏。
- 纯逻辑（格式读写和校验、命令和撤销重做、选择、吸附、框选、瓦片刷、复制粘贴、平台跳跃加载关卡文件）都有测试。

## 做法

### 分层

| 位置 | 内容 |
|---|---|
| `ts/level.ts` | 通用的关卡文件格式：类型、`parseLevel`（校验）、`formatLevel`（格式化）、`emptyLevel`；不知道有哪些实体类型 |
| `ts/nge.tsx` | `screenToWorld` / `worldToScreen`：和引擎 `Camera2d` 的换算一样（不转的相机），编辑器拾取用 |
| `examples/platformer/catalog.ts` | 平台跳跃的实体类型表：名字、默认尺寸、属性（类型、范围）、编辑器里画成什么样 |
| `examples/platformer/levels.ts` | `fromFile`：关卡文件 → `Built`（游戏用的关卡）；`toFile`：`Level`（代码描述的关卡）→ 关卡文件 |
| `examples/platformer/preview.ts` | `previewOf(entity)`：编辑时实体画成什么（精灵、模型、灯），不带刚体 |
| `examples/platformer/game.tsx` | 原来 `App.tsx` 里的游戏组件，多了可选的 `trial` / `onExit`：编辑器试玩时只给一关、不读写存档、不联网 |
| `examples/editor/*.ts` | 编辑核心：命令和历史、选择和框选、吸附、视图、瓦片刷、复制粘贴、指针工具状态机、文件、属性输入；都是纯函数 |
| `examples/editor/store.ts` | 编辑器的状态（signal）和操作：界面只调它，测试直接调它 |
| `examples/editor/scene.ts` | 编辑时的场景：实体预览、网格线、选中框、框选框 |
| `examples/editor/App.tsx`、`panels.tsx` | 界面：工具栏、场景树、物件库、画布、属性面板、文件面板、快捷键；编辑 / 试玩切换 |
| `examples/editor/src/lib.rs` | 游戏视图注册成平台跳跃的引擎（`platformer::app`） |

取舍：
- **编辑器写在 TSX 里，引擎不加编辑模式**。关卡流程本来就在 TSX（engine-design.md 的关键设计决策 2），编辑操作都是低频的离散事件（按下、拖动、松开），每次改完重新声明场景就行，引擎的增量同步只动变了的节点。编辑时场景里不放角色、不给刚体和关节、`timeScale: 0`：物理、补间、动画都停着，平台跳跃的 Rust 系统找不到角色什么也不做。所以引擎这边只加了 TSX 的坐标换算，没有新的 Rust 代码。
- **拾取在 TSX 里按包围盒算**，不用引擎的 `tap`：`tap` 只在按下时发、只认可点的精灵，框选、拖动、点空白处都要自己算；实体的包围盒由类型表给（模型、灯、铁链这种没有精灵的也能点），按场景树的顺序从上往下找。视图不转，换算就是平移加缩放，和 `Camera2d::screen_to_world` 一样。
- **试玩是同一个进程里换一个组件**：编辑器把正在编辑的关卡转成 `Built`，渲染平台跳跃的游戏组件（新的游戏视图，引擎从头建），Esc 回来时编辑器组件重新挂上。编辑状态放在编辑器组件外面（`store`），挂上去时原样恢复。没有把关卡交给另一个进程：省掉进程间传文件，也省掉第二个窗口。
- **文件存在编辑器的 `levels/` 目录**。nsh 没有系统的打开 / 保存对话框（只有挑照片的 `Picker`），`fs/promises` 只能读写 `nsh.json` 授权的目录，授权的路径不能带 `..`：编辑器授权 `${pluginDir}/levels`，只读写自己目录下的 `levels/`。打开 / 另存为是编辑器里的文件列表和文件名输入框。第一次存取时先列一下目录，列不出来（没有权限，比如无界面的测试）就存进应用存储（`Storage`，键是 `editor:level:<文件名>`），状态栏说存在哪。平台跳跃 `import "../editor/levels/stairs.json"`（打进包里，iOS / web 照样有），在编辑器里改完保存，平台跳跃下次运行就是新的。

### 关卡文件（`ts/level.ts`）

```json
{
  "format": "nge-level",
  "version": 1,
  "name": "石阶",
  "night": false,
  "tiles": [
    { "id": "level", "texture": "asset:/@platformer/tiles.png", "grid": [3, 1], "tile": 32,
      "cols": 72, "rows": 15, "x": 0, "y": 448, "solid": [0, 1, 2],
      "data": [
        [0, -1, -1, …],
        …
      ] }
  ],
  "entities": [
    { "id": "e1", "type": "coin", "name": "金币", "x": 192, "y": 28 },
    { "id": "e2", "type": "lift", "x": 864, "y": -8, "w": 64, "props": { "dx": 128, "duration": 2.2 } }
  ]
}
```

- `format` 固定是 `"nge-level"`，`version` 现在是 1；比 1 新的不读（报「是更新的编辑器存的」），缺了或不是正整数的报错。
- `tiles`：瓦片层，和 `TilemapNode` 一样（左上角在 `(x, y)`，`y` 朝上），但 `data` 是二维的（`rows` 行、每行 `cols` 个），存成文件时一行一行好看，也省得算下标。帧号是整数，-1 是空格，不能超过图集的格子数（`grid` 的乘积）。
- `entities`：按场景树的顺序（越往后画在越上面、点选时先命中）。`id` 非空、不重复、不超过 64 个字；`type` 非空；`x` / `y` 是中心的世界坐标（point，y 朝上）；`w` / `h` 可选，不写用类型的默认尺寸；`name` 可选（场景树上显示）；`props` 是类型专属的属性，值只能是有限数、布尔、字符串。灯和 3D 模型也是实体（类型 `light`、`model`），在场景树里一样选中、移动、撤销。
- 其他顶层字段：`name`（关卡名）、`night`（夜里：开 2D 光照和暗角）。
- 校验：数都是有限的、坐标不超过 ±1e6；瓦片层最多 2000 列 × 500 行；实体最多 5000 个；字符串不超过 256 个字、没有控制字符。`parseLevel(text 或 已解析的值)` 返回 `{ ok: true, level }` 或 `{ ok: false, errors }`，每条错误带路径（`entities[3].x 要是有限的数`），最多 20 条。
- 实体的类型由游戏的类型表另外查（`checkTypes(level, catalog)`）：不认识的类型、属性类型不对、超出范围的数报错。
- `formatLevel(level)`：两个空格缩进，瓦片每行一行、实体每个一行，结尾换行；`parseLevel(formatLevel(l))` 等于 `l`。

### 平台跳跃的实体类型（`catalog.ts`）

| 类型 | 名字 | 默认尺寸 | 属性 | 游戏里 |
|---|---|---|---|---|
| `spawn` | 出生点 | 24 × 32 | | 角色的起点；没有时在 (96, 16) |
| `coin` | 金币 | 14 × 14 | | 金币 |
| `enemy` | 敌人 | 24 × 24 | `patrol` 往右巡逻几格（1–20，默认 3） | 来回巡逻，能踩 |
| `ghost` | 幽灵 | 22 × 22 | | 看见角色就追 |
| `lift` | 移动平台 | 64 × 16 | `dx` / `dy` 往哪走（像素，只能给一个）、`duration` 一趟几秒（0.2–30） | 来回走的平台 |
| `crate` | 3D 箱子 | 40 × 40 | | 能推的箱子 |
| `swing` | 铁链 | 20 × 92 | | 支点在 (x, 顶边) 的铁链吊球 |
| `goal` | 终点 | 16 × 80 | | 终点和旗子（关卡里恰好一个） |
| `ramp` | 斜坡 | 96 × 32 | `down` 往右下降（布尔） | 角色能走上去的斜坡 |
| `tower` | 箱子堆 | 48 × 44 | | 一摞 3D 箱子、篝火、聚光灯（最多一个） |
| `jelly` | 果冻 | 48 × 30 | | 靠近时压一压的果冻（最多一个） |
| `light` | 灯 | 16 × 16 | `kind`（point / spot）、`color`、`intensity`、`range`、`z` | 3D 灯 |
| `model` | 模型 | 40 × 40 | `model`（`asset:/` 路径）、`scale`、`z`、`spin` | 摆着看的 3D 模型 |

- `preview.ts` 的 `previewOf(entity)`：编辑时画成什么（精灵、模型、灯），用游戏里同样的颜色、尺寸和模型，去掉刚体；敌人多画一条巡逻线、移动平台多画一个终点的虚影；不认识的类型画成洋红色的方块。
- `fromFile(level)` 转成 `Built`：瓦片层直接变成瓦片地图，实体按类型生成，id 按类型编号（`enemy-0`、`coin-3`），游戏的约定（敌人以 `enemy-` 开头）不变。必需的（终点、箱子）缺了报错；校验没过的不转。
- `toFile(level: Level)`：代码描述的关卡转成关卡文件（编辑器的「导入」不做，用它导出了「石阶」）。测试里把「草原」导出再转回来，和 `build(草原)` 生成的关卡逐项比（位置误差 < 0.01）。

### 编辑核心

全是纯函数，输入旧状态、返回新状态，不改参数（`examples/editor/`）：

- `history.ts`：命令模式。命令是 `{ label, apply(level), revert(level) }`，都返回新关卡。`History` 记 `done` / `undone` 两个栈，最多 200 步；新命令清掉 `undone`；`savedAt` 记保存时的位置，`dirty` 是当前位置和它不一样。同一批方向键微移（同一组实体、600 ms 以内）合并成一步。
- `commands.ts`：加实体（插在某个位置）、删实体（记下原来的下标，撤销时放回去）、移动（一组 id 和位移）、改字段（id、旧值、新值：重命名、属性面板）、排序（上移 / 下移 / 移到最前 / 最后）、画瓦片（一组 `[层, 行, 列, 旧, 新]`）、改瓦片层大小（记下整层旧数据）、改关卡设置、一组命令合成一步。
- `select.ts`：点选（从上往下第一个包围盒含这个点的，太小的东西按屏幕上 4 point 的半径算）、框选（包围盒和框相交的）、切换选择（shift 点选）、删掉的实体从选择里去掉。
- `snap.ts`：吸附到网格：比格子大（或一样大）的左边 / 下边对齐格线，比格子小的放在格子正中；网格 0 是不吸附。
- `view.ts`：视图 `{ x, y, zoom }`；按住拖动平移；以某个屏幕点为中心缩放（点下的世界坐标不动），缩放限制在 0.25–4。
- `tiles.ts`：世界坐标 → 格子；拖动时两点之间按直线补齐格子（快速拖动不漏格）；同一笔内重复的格子只记一次；画上去和原来一样的格子不记。
- `clipboard.ts`：复制选中的实体（深拷贝），粘贴 / 原地复制时换新 id（`e<n>`，不和已有的重）、名字加「副本」、偏移一格，粘贴后选中新的。
- `tool.ts`：画布上的指针状态机：按下 / 移动 / 松开 → 预览和最后提交的命令。选择工具：按在选中的实体上拖动是移动（松开时一个移动命令，吸附按第一个选中的实体），按在没选中的实体上先选中再拖，按在空白处是框选；平移工具；放置工具（点一下放一个物件库里选中的类型，吸附）；瓦片刷和橡皮。拖动不到 3 point 算点击。
- `files.ts`：文件名校验（字母数字、`-`、`_`、中文，`.json` 结尾自动补）、打开（读不出、格式不对都返回错误不抛）、保存（格式化）。读写通过一个 `LevelStore` 接口，界面用 `fsstore.ts`（目录或应用存储），测试用内存里的实现。
- `fields.ts`：属性面板的一个输入框 → 实体的改动：数要是有限数、在范围里；站在地上的（箱子堆、果冻）不能改 y；固定大小的不能改宽高；名字不能有控制字符。不合规的返回原因。
- `store.ts`：把上面这些串起来：执行命令时同时更新选中（去掉已经没有的），新建 / 打开前有修改就问（保存 / 不保存 / 取消），另存为已有的文件问要不要覆盖，试玩前查关卡合不合规。

### 界面（`examples/editor/App.tsx`、`panels.tsx`）

- 顶上工具栏：新建、打开、保存、另存为、撤销、重做（没得撤销时灰掉）、工具（选择 V、平移 H、放置 P、瓦片刷 B、擦除 E）、网格（32 / 16 / 不吸附）、缩小 / 放大和缩放比例、试玩。
- 左边上半是场景树：每行是类型名、名字和 id；点一下选中，按着 shift 点加选 / 减选；下面的按钮上移、下移、复制、删除。改名在右边的属性面板里。
- 左边下半是物件库（每种类型一个按钮：点了在视图中间放一个、选中它、切到放置工具，接着点画布继续放）和瓦片（石块、草地、木板、擦除：点了切到瓦片刷）。
- 中间画布：游戏视图（`captureKeys={[]}`，键盘留给快捷键）。场景是 `scene.ts` 生成的：实体预览、网格线、选中框（蓝色描边，线宽随缩放不变）、框选框；没有刚体、关节，`timeScale: 0`。拖动时画的是预览（移动中的实体、正在画的瓦片），松开才执行命令。
- 右边属性面板：选中一个时是名字、x、y、宽、高（只有能改大小的类型有）和类型的属性（数、文字是输入框，布尔和选项是一排按钮）；输入框回车或失焦时提交，不合规的在下面用红字说原因、值不变。选中多个时显示个数；没选中时是关卡设置（名字、夜里、宽、高；改高度时地面跟着底边走）。
- 底下状态栏：上一条消息（保存了、打不开、为什么不能试玩）和文件名，有没保存的修改时带 ●；窗口标题也一样。
- 打开 / 另存为是叠在上面的文件面板：`levels/` 里的文件列表，另存为多一个文件名输入框。

快捷键（`keymap`，`when: "notEditing"`：输入框有焦点时不响应，打字、删字不受影响）：

| 键 | 作用 |
|---|---|
| Delete / Backspace | 删除选中 |
| ⌘Z / ⌘⇧Z（⌘Y） | 撤销 / 重做 |
| ⌘D | 原地复制（偏移一格） |
| ⌘C / ⌘V | 复制 / 粘贴 |
| ⌘A | 全选 |
| ⌘S / ⌘⇧S | 保存 / 另存为 |
| ⌘N / ⌘O | 新建 / 打开 |
| 方向键 / ⇧+方向键 | 选中的微移 1 point / 一格（连着按合成一步撤销）；没选中时平移视图 |
| V / H / P / B / E | 选择 / 平移 / 放置 / 瓦片刷 / 擦除 |
| ⌘+ / ⌘- | 放大 / 缩小 |
| ⌘R / F5 | 试玩 |
| Esc | 试玩时回到编辑；编辑时关掉文件面板或取消选择 |

### 试玩

- 按试玩时先 `checkTypes`、再 `fromFile`：不合规（比如没有终点）就在状态栏报错，不进试玩。
- 平台跳跃的游戏组件（`game.tsx` 的 `Game`）收到 `trial: { name, built, night }` 时是试玩模式：只有这一关，不读写存档、不联网、不按数字键选关、不拿排行榜，通关后从头再来，顶上说「试玩，按 Esc 回到编辑」；`onExit` 给了时 Esc 叫它（`keymap`，游戏视图的 `onKey` 里也接了一次）。
- 编辑器在试玩时整个换成 `Game`（工具栏、场景树都不在，快捷键跟着组件解绑），Esc 回来时重新挂上编辑界面；状态都在 `store` 里，关卡、选中、视图、撤销历史都还在。
- 编辑器的游戏视图注册的就是平台跳跃的引擎（`platformer::app`），编辑和试玩是同一个原生组件。

### 平台跳跃

- `App.tsx` 只剩 `mount(() => <Game />)`，游戏组件挪到 `game.tsx`。
- `LEVELS` 第二关「石阶」从 `../editor/levels/stairs.json` 读（`fromFile`）；第一关「草原」还是代码，第三关还是 Tiled。
- `Built` 多了 `spawn`（出生点）、`lights`（额外的 3D 灯）、`models`（摆着看的模型）、敌人的 `y`；代码和 Tiled 的关卡按原来的值填，行为不变。

## 不做

- 系统的打开 / 保存对话框（nsh 没有）；文件只在编辑器的 `levels/` 目录里。关窗口时不拦（nsh 没有关窗口前的回调），标题上的 ● 提醒有没保存的。
- 多个瓦片层的编辑（读写都支持，刷子只画第一层）、瓦片层的视差、换图集。
- 旋转实体、改实体的 z、组 / 父子层级（场景树是平的）。
- 编辑器里改 Tiled 地图；导入 Tiled 或代码描述的关卡（代码描述的用 `toFile` 一次性导出）。
- 鼠标滚轮缩放、悬停高亮、拖动画布边上自动滚动（缩放用按钮和 ⌘+ / ⌘-）。
- 多人同时编辑、自动保存、崩溃恢复。

### 修过的问题

- 格式化关卡时，名字里带 `":` 或 `,"` 的字符串被拆坏：改成每个值单独 `JSON.stringify` 再拼。
- 历史超过 200 步丢掉最早的之后，撤销到底被当成「和保存时一样」：加了 `base`，记最后丢掉的那一步。
- 在属性面板改了一项后撤销，`updateEntity` 的标签判断写错（`"patch" in patch`），撤销记录的名字不对。
- 敌人加了 `y` 以后，Tiled 导入的测试期望没跟着改。
- 游戏组件挪到 `game.tsx` 后，平台跳跃 Rust 测试里 `include_str!("../App.tsx")` 查声音和敌人 id 的两个测试读到的只剩挂载代码而失败：改成读 `game.tsx`。
