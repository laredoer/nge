# 存档槽：多个存档、版本升级、坏档不崩

> 前置：关卡切换和存档（[levels.md](levels.md)）。

## 目标

现在只有 `saved(key, initial)`：一个 signal 存一个 JSON，结构变了靠读的地方自己补齐，坏了就悄悄用初始值。做不了「三个存档位，显示每个存的是什么、什么时候存的」，也没有版本号，改了存档结构只能一路兼容下去；存档坏了也分不清是空的还是坏的。

**验收标准**：
- 一个游戏有几个存档槽，每个槽存一份结构化的数据，带版本号、保存时间和一段给列表显示用的概要。
- 读档时按版本号一级一级升级到当前版本；比当前还新、缺升级函数、JSON 坏了、数据不对的，都报成坏档，不覆盖、不崩。
- 能列出所有槽（空的、有档的、坏的），能存、读、删，能找到最近存的那个。
- 旧的 `saved()` 存档能直接接过来当第一个槽，不丢进度。
- 平台跳跃：三个存档位，各存各的进度和打到第几关；按 S 换到下一个存档位，从它存的那关接着玩；以前 `saved` 存的进度自动进第一个存档位。

## 做法

### `ts/saves.ts`（从 `ts/nge.tsx` 导出）

```ts
const slots = saveSlots<Data, Summary>({
  key: "platformer",
  slots: 3,
  version: 2,
  migrations: { 1: (old) => ({ progress: old, level: 0 }) },
  parse: (data) => dataOf(data),        // 补齐、校验；抛异常算坏档
  summary: (data) => ({ unlocked: data.progress.unlocked }),
  adopt: { key: "platformer", version: 1 },
});
```

- 每个槽是 nsh `Storage` 里的一个键 `nge:save:<key>:<槽号>`（槽号从 0 数），值是 `{ "v": 版本, "at": 保存时间（毫秒）, "summary": 概要, "data": 数据 }`。
- `slots.list()`：signal，每个槽一项：
  - `{ status: "empty" }`
  - `{ status: "ok", savedAt, version, summary }`：列表只读外面这层，不跑升级和 `parse`。
  - `{ status: "broken", reason }`：JSON 坏了、外层结构不对、版本比当前还新（这种带 `newer: true`：是更新的游戏存的，不要覆盖，回到旧版本游戏时覆盖会丢掉新版本的进度）、存储读出错。
  - 读完之前是空数组；`slots.ready()` 读完了才是 `true`，`slots.loaded` 是读完时 resolve 的 `Promise`。
- `slots.load(slot)`：`Promise`，结果是 `{ status: "empty" }`、`{ status: "ok", data, savedAt }` 或 `{ status: "broken", reason }`。
  - 版本比当前旧：从 `migrations[v]` 开始一级一级升到当前版本，缺了哪一级就是坏档。
  - 升级完交给 `parse`，抛异常就是坏档，`reason` 带上异常信息。
  - 槽号超出范围或不是整数：直接 reject（是写错了代码，不是坏档）。存储读出错不 reject，是坏档。
  - 升级函数要是同步的。
- `slots.save(slot, data)`：写当前版本、现在的时间、`summary(data)`（没给 `summary` 时没有概要），写完按写进去的 JSON 更新 `list`（和下次启动读出来的一样）。写失败（存储满了）reject，`list` 不变，原来的档还在。
  - 写之前按读档的规矩检查一遍：`data` 是 `undefined`、时间不是有限数时 JSON 里会丢掉或变成 `null`，下次读就是坏档，这种直接 reject，不写。
- `slots.remove(slot)`：删掉，`list` 里变成空。
- `slots.latest()`：`list` 里 `savedAt` 最大的 `ok` 槽号，一个都没有是 `null`。
- `adopt: { key, version }`：第一个槽是空的、`saved(key)` 的旧键 `nge:<key>` 有值时，把旧值当成这个版本的数据放进第一个槽（列表里显示成 `ok`、保存时间 0；第一次 `save` 时才真的写进新键）。旧键不删，回退到旧版本时进度还在。第一个槽存过或删过以后记一个 `nge:save:<key>:adopted`，以后不再接：删掉的档下次启动不会又冒出来。删的时候先写标记再删，标记写不上就不删；存的时候标记写不上不算失败（槽里有档就不会接旧档）。接过来的档在列表里没有概要。
- 存储用 nsh 的 `Storage`；测试传 `store`（有 `getItem` / `setItem` / `removeItem` 就行）和 `now`。
- 所有读写（读列表、`load`、`save`、`remove`）排成一队，一个做完再做下一个：列表读完之前就存的排在后面，读档的几次读之间不会被存档插进来。同一个槽连着存，后存的为准。
- `slots`、`version` 不是正整数，`adopt.version` 比 `version` 大时直接抛。

### 示例（平台跳跃）

- 存档数据第 2 版：`{ progress: { unlocked, best }, level }`。第 1 版是以前 `saved("platformer")` 存的进度，升级时 `level` 是 0。
- 开始时读最近存的槽（没有就是第一个）；HUD 显示「存档 n」。
- 通关、换关（新关卡建好）时存进当前槽。存档位读出来之前不存：开局那一关的 `levelStart` 不能把还没读出来的档覆盖掉。
- 连着按几次 S 时按顺序往下数（不等读档回来），读档晚到的只认最后一次。
- 「新版本存的」坏档位永远不覆盖；别的坏档位在上面通关一次后覆盖，写成功了才去掉「坏了」。
- 按 S 换到下一个槽：读它的进度，从它存的那关开始。空槽从第一关开始；坏槽在 HUD 上标「存档 n 坏了」，不覆盖，直到在它上面通关一次。

## 不做

- 云同步、多设备合并。
- 存档加密、防改。
- 自动定时存档：游戏在合适的时候自己调 `save`。
- 存 Rust 侧的状态（刚体位置等）：游戏状态在 TSX 的 signal 里，要存的自己放进数据。

## 修过的问题

- 列表读完之前存档，列表停在读出来的旧值上；读档的几次读之间被存档插进来，读回了旧档。所有读写改成排队。
- `data` 是 `undefined` 或时间是 NaN 时写出坏档，内存里的列表却显示正常；写之前先自检。
- 删第一个槽时先删后写标记，标记写不上时旧档下次又冒出来；改成先写标记。存档时标记写不上整个存档 reject，槽其实已经写了；改成不算失败。
- 存储读出错时 `load` reject，示例没接住、之后再也不存；改成坏档。
- 版本太新的坏档在旧版本游戏里通关会被覆盖，丢掉新版本的进度；加 `newer`，示例不覆盖。
- 示例连着按 S 两次都换到同一个存档位；按要换到的那个往下数。
- 示例读档前碰到终点会用新进度覆盖第一个存档位；读完才存。
- 坏档位上存档失败时「坏了」的标记也去掉了；写成功才去掉。

## 验收

- `saves.test.tsx`（平台跳跃里，用内存里的 `store`）：
  - 空的、有档的、坏的（JSON 坏、外层不对、版本太新）各自列出来；`ready` 读完才是真。
  - 存了再读、存完 `list` 跟着变、`latest` 找最近的、删了变空。
  - 升级一级一级走；缺升级函数、`parse` 抛异常都是坏档并带原因。
  - 写失败时 reject、`list` 不变。
  - 槽号不合法 reject；参数不对直接抛；存储读出错是坏档；版本太新带 `newer`。
  - 列表读完之前存，列表是存进去的那份；存不成 JSON 的数据、NaN 时间 reject 不写。
  - 删第一个槽时标记写不上就不删；存档时标记写不上不算失败。
  - `adopt` 接过旧存档；第一个槽有档时不接；删过以后不再接；旧档坏了是坏档。
- 平台跳跃：存档数据的升级和补齐、换槽的顺序。
- 变异检查：坏 JSON、外层的版本和 data、版本太新、读完才更新列表、升到当前版本、缺升级函数、`parse`、写失败 reject、存完和删完更新列表、最近的槽、槽号是整数和上限、有档不接旧档、删过不再接、旧档坏、存概要；示例的没解锁的关、负的关卡号、第 1 版升级、换存档位回到第一个，改掉都有测试报错。
- 还没手测：在真设备上换存档位。
