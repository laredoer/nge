# 2.5D：3D 相机的正交模式和跟随 2D 相机

> 前置：基础 3D（[m4-3d.md](m4-3d.md)）、TSX 场景节点（[scene-nodes.md](scene-nodes.md)）、2D 相机（[camera.md](camera.md)）。

## 目标

做「3D 画面、2D 玩法」的游戏（横版里角色和场景是 3D 模型）：

- 3D 相机可以用正交投影，远近一样大，横版、等距视角不变形。
- 3D 相机可以直接跟着 2D 相机走：3D 的一个单位就是 2D 的一个 point，模型放在 (x, y, 0) 就在 2D 世界的 (x, y)，和精灵、物理、相机跟随、震屏对得上，不用自己同步。

**验收标准**：平台跳跃的终点处放一个转着的 3D 箱子（glTF），`camera3d: { match2d: true }`；角色往前跑、相机跟随和震屏时，箱子始终在关卡里的同一个位置，和瓦片对齐。

## `Camera3d`（`nge-render3d`）

- 新字段 `ortho: Option<f32>`：`Some(h)` 是正交投影，画面竖直方向能看到 `h` 个世界单位（横向按宽高比）；`None` 是原来的透视（`fov_y`）。`h` 不是正数或不是有限数时按透视。
- `view_proj` 按 `ortho` 选投影矩阵；点击模型的射线拾取用 `view_proj` 的逆矩阵算近、远两个点，正交下射线自然是平行的，不用改。
- 光照的高光要知道视线方向。透视时是相机到片元的方向；正交时所有片元都用同一个方向（朝向相机，相机的 +Z）。`Camera3d::eye` 给着色器一个 `Vec4`：w = 1 是相机位置，w = 0 是这个方向。

## TSX：`camera3d`

```tsx
camera3d: { ortho: 600 }                 // 正交，竖直方向看到 600 个单位
camera3d: { match2d: true, z: 1000 }     // 跟着 2D 相机
```

- `ortho?: number`：同上。
- `match2d?: boolean`：每帧（2D 相机跟随、震屏之后，渲染之前）把 3D 相机设成：
  - 正交，`ortho` = 视口高度 / 2D 相机的 `zoom`；
  - 位置是 (2D 相机的 x, y, `z`)，`z` 默认 1000，看向 -Z，绕 Z 轴的转角和 2D 相机一样；
  - 近平面是 0，远平面跟着 `z` 放到 2 × `z`，模型的 z 在 [-`z`, `z`] 之间都看得到。

  开着时 `x`、`y`、`target`、`fov`、`ortho` 都不看。
- 只改声明里的其他字段（比如环境光）不会把 Rust 移动过的相机拉回去，这一点不变。`camera3d` 的声明变了时，位置、朝向、`fov`、`ortho` 按声明重设，Rust 设的近远平面留着；刚关掉 `match2d` 时近远平面回到默认。`match2d` 开着时每帧都覆盖。

## 先后

- 3D 先画、2D 精灵后画，所以精灵总在模型上面。3D 模型之间用深度缓冲，和精灵之间不按 z 混排。要让模型挡住精灵，以后再做。

## 不做

- 阴影、透视的 2.5D（视差背景可以用多层精灵）、3D 物理。
- 2D 物理直接驱动 3D 模型：模型节点的位置由 TSX 声明。要跟着刚体走，现在得用 Rust 系统把 `Transform2d` 抄到 `Transform3d`。

## 实现

- `match2d` 开着时，`sync_camera3d` 给场景相机加 `Match2d { z }` 组件；`match_2d` 在 `PostUpdate` 里、2D 相机跟随和震屏（`camera_rig`）之后每帧设 3D 相机。关掉时去掉组件，按声明重设相机。
- `match_2d` 每帧跑两次：`PreUpdate` 里场景同步之后（场景变化和点击同一帧到达时，点模型用的是新相机，和点精灵一样），`PostUpdate` 里 2D 相机跟随、震屏之后。第二次必须排在 `camera_rig` 之后，不然震屏和跟随晚一帧。
- 节点的 `z` 改成可选：不填时普通相机是 6（和原来一样），`match2d` 是 1000。`Camera3dNode::z` 从 `f32` 改成 `Option<f32>`，对直接构造它的 Rust 代码是不兼容的改动（JSON / TSX 不受影响）。
- 着色器里视点字段从 `camera_pos` 改名 `eye`：正交时装的是方向。
- 平台跳跃的箱子和 `examples/model` 的是同一个文件，由 `tools/gen_glb.py` 生成。

## 验收记录

- `cargo test --workspace` 通过：`Camera3d` 正交投影远近一样大、横向按宽高比、坏的 `ortho` 按透视、`eye` 在两种投影下的值；离屏渲染里正交相机离得近、离得远画出来一样大，平面上的高光处处一样亮；场景里声明 `ortho`、`match2d` 跟 2D 相机的位置 / zoom / 转角 / 震屏（z = 0 平面上的点两个相机投到同一处）、关掉后回到声明的相机。变异检查：着色器不区分 w、转角方向反了、不设远平面、宽和高用反（测试用 200×100 的视口）、近平面不是 0、声明变化时总是重置近远平面、关掉 `match2d` 不重置、`PreUpdate` 不对齐（同一帧的点击打不中），各有测试会失败。斜着看的正交相机的 `eye` 也有测试。
- 平台跳跃终点前放了一个转着的箱子（`crate.glb`，放大 40 倍）。Mac 上 `nsh run` 手测：箱子在终点前转着，相机跟着角色走时贴着关卡不动。
