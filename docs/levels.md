# 关卡切换和存档

> 前置：声明式场景（[m3-tsx.md](m3-tsx.md)）、2D 相机（[camera.md](camera.md)）、平台跳跃示例（[platformer.md](platformer.md)）。

## 目标

现在一个游戏只有一个场景。要做第二关，TSX 只能把整个 `scene` 换掉，引擎按 id 增量同步。这样有几个问题：

- 两关里同 id 的节点（`player`、`goal`、`enemy-0`）被当成同一个实体，只改了声明的字段。Rust 改过的位置、速度、补间、动画进度都被带进新关卡。
- 上一关的一次性效果（爆出来的粒子、飘字）留在新关卡里。
- 相机从上一关的位置平滑地跟到新的起点，一路扫过去。
- Rust 系统不知道换了关，自己记的状态（平台跳跃的重生点、掉坑次数、踩过的敌人）也带过去了。

存档也没有：通关进度、最好成绩，一关掉就没了。

**验收标准**：
- `scene.level` 换了值（比如从 `"1"` 到 `"2"`），场景里的实体全部重建，同 id 的也一样。
  - 上一关的补间、一次性粒子、飘字都清掉。
  - 跟随的相机直接对准新目标。
  - Rust 能读到 `LevelStart` 消息。
- 值没变的时候，场景照常增量同步，和以前一样。
- 平台跳跃有两关：通关后进下一关，最后一关通关后回到第一关。每关的最好成绩和解锁到第几关存在设备上，重开以后还在。

## 做法

### 引擎：`scene.level`

- **字段**：`Scene` 加 `level: Option<String>`。TSX 写数字也行，按字符串比较；整数不管传过来是 `1` 还是 `1.0`，都算 `"1"`。
- **换关系统**：`PreUpdate` 里，在所有同步系统之前跑一个独占系统。`level` 和上一次见到的不一样时（包括第一次声明），它做这几件事：
  - 删掉所有带 `SceneId` 的实体（声明出来的节点）和它们的子实体（瓦片）。
  - 删掉一次性的效果：带 `FloatingText` 的飘字，`despawn_when_done` 的粒子发射器。
  - 补间是实体上的组件，跟着实体一起删掉。
  - 相机设成重新开始跟随（下一帧直接对准目标），停掉震屏。
  - 发 `LevelStart { level }` 消息给 Rust 系统，同时发 `levelStart` 事件给 TSX。
- **之后**：同步系统看到没有旧实体，按新声明全部重建。
- **不清的东西**：
  - 场景外的东西：Rust 自己 spawn 的实体、`Time`、声明过的相机、背景色、重力、背景音乐，都由各自的声明管。
  - 正在响的一次性音效。
- **换关后的命令**：要对新关卡发的命令（`tween` 等）放在 `onLevelStart` 里发。这个事件在新实体建好的那一帧发出，之后到的命令一定落在新关卡上，不依赖 nsh 什么时候把新场景推给引擎。和换关同一帧到达的命令也落在新实体上（命令在 `Update` 才生效）。
- **补间的结束事件**：换关删掉的补间不补发 `tweenEnd`，等着它的 TSX 要在换关时自己放下。

### TSX：存档

`ts/nge.tsx` 加 `saved(key, initial)`，返回一个 signal：

- **读**：一开始是 `initial`，从 nsh 的 `Storage` 读到以后换成存的值。存的不是合法 JSON 时，警告一次，用 `initial`。
- **写**：`set` 时同时写进 `Storage`。写失败（满了）时只打日志，内存里的值照样更新。
- **键名**：key 加上前缀 `nge:`，免得和别的东西撞上。

### 平台跳跃

- **关卡数据**：挪到 `levels.ts`，每关是一份数据：坑、平台、台阶、金币、移动平台、敌人、3D 箱子、终点。
- **App.tsx**：按当前关卡生成场景，`level` 写「关卡号-第几局」（如 `"2-3"`），所以选同一关也重开一局。局数从启动时间起数，开发时只重载 JS 也算换关。`onLevelStart` 只认当前这一局的，连着选两次关时晚到的那个不算。关卡号和局数放在一个 signal 里，一次换关只发一次场景。
  - 通关后等 1.5 秒进下一关，最后一关之后回第一关。
  - 换关用 `batch` 把清状态和换关收成一次场景更新；移动平台和敌人的补间在 `onLevelStart` 里发（第一次进游戏也是）。
  - 换关后到 `levelStart` 之前收到的 `collide`、`respawn`、`stomp` 是上一关路上的，丢掉：两关有同名的金币和敌人。
  - 通关后 1.5 秒内按 R 或选关，取消自动进下一关。
- **存档**：`saved("platformer", { unlocked: 1, best: {} })` 记解锁到第几关、每关最好的用时。读的时候用 `progressOf()` 补齐：以前的版本存的、结构不对的，缺什么按新存档算。HUD 显示当前关卡、最好成绩和解锁了几关。数字键 1、2 选已经解锁的关卡，用游戏视图的 `onKey`（数字键默认就被游戏吞掉）。存档怎么变由 `levels.ts` 的 `finish()` 算：解锁的只往前走，用时更短才记。
- **Rust 控制器**：读到 `LevelStart` 时，把 `Controller` 重置成默认值。重生点会在新关卡第一次见到角色时重新记。

## 不做

- 换关的过场动画：TSX 可以自己做，用一个 `parallax: 0` 的全屏精灵补间 `alpha`。
- 异步预加载下一关的资源。资源本来就按 uri 缓存，第二次用不重新加载。
- Rust 侧的存档 API：存档放在 TSX，关卡流程和状态机本来就在 TSX（见 engine-design.md 的关键设计决策 2）。
- 存档迁移、云同步。

## 验收

- `nge-scene` 的 `level.rs`：
  - 同一关（`1` 和 `"1"` 算同一关）不重建，换关全部重建。
  - 换关清掉补间、飘字、一次性粒子。
  - `LevelStart` 每关只发一次。
  - 相机直接对准新目标。
  - 变异检查：去掉相机重置、不删飘字、不删粒子，都有测试失败。
- 平台跳跃 Rust：`a_new_level_resets_the_spawn_and_the_falls`，第二关的起点不同，掉坑次数从 0 数，送回第二关的起点。不读 `LevelStart` 时失败。
- `nge-scene` 另外三个：TSX 收到 `levelStart`（只在换关时、发出时新实体已经在了）；`1`、`1.0`、`"1"` 是同一关；换关停掉震屏（去掉停震屏时失败）。
- 平台跳跃 TSX（`nsh test`）：
  - 存档里的最好成绩显示在 HUD 上。
  - 没有存档、存档坏了、结构不对都从头开始，存档不被改写。
  - `progressOf()`：缺的补上，越界的收回来，不是数字的用时丢掉。App 里不经过它直接读存档的变异测不出来：nsh 吞掉 HUD 里一个表达式的异常，留着上一次的文字，和对的结果一样。
  - `finish()`：解锁下一关，用时更短才记，最后一关不越界，重玩前面的关不退回。
  - 变异检查：`saved()` 不读存档时失败。
- **修过的问题**：第二关开局角色就压着一枚金币；第二关第一个敌人头顶的平台太低，踩它时撞头；补间依赖 nsh 同步推场景，改成在 `levelStart` 里发；换关时清状态发了好几次旧关卡的场景，改用 `batch`；存档结构不对时 HUD 和通关会抛异常；JS 的整数以 `1.0` 传过来时和 `"1"` 不是同一关；`saved().update` 在 effect 里调用会产生依赖；连着选两次关时前一次的 `levelStart` 晚到，提前放行了上一关路上的事件；只重载 JS 时关卡号没变，收不到 `levelStart`，游戏卡住。
- 还没手测：Mac 上两关来回、数字键选关、重开后存档还在；iPhone 上通关进下一关。
