# M4：基础 3D

> 前置：M1 的 2D 渲染、M3 的场景同步已完成。

## 目标

在同一个引擎里加上基础 3D：网格、深度缓冲、3D 相机、简化的 PBR 材质、方向光和点光源、glTF 加载。2D 精灵可以叠在 3D 画面上（HUD、粒子）。

**验收标准**：`examples/model` 加载一个带贴图的 glTF 模型并显示出来（Mac 上实跑，加上离屏渲染出图核对）。

## 选型

| 用途 | 库 | 原因 |
|---|---|---|
| glTF | `gltf` 1.4（只开 `import` / `utils`） | 事实标准；依赖的 image 0.25 和我们一致 |
| 投影 | `glam::camera::rh::proj::directx::perspective` | WebGPU 的 NDC：Z ∈ [0, 1]、Y 朝上 |

## 新增 crate：`nge-render3d`

不依赖 `nge-render2d`，自带一个 3D 资源库 `Assets3d`（贴图、网格、材质、模型）。两边的纹理暂时各存一份，统一的资源层放到 M5（`nge-assets`）。

### 组件和资源

| 名字 | 说明 |
|---|---|
| `Transform3d` | `translation: Vec3`、`rotation: Quat`、`scale: Vec3`；`looking_at(target, up)` |
| `Camera3d` | `fov_y`（弧度）、`near`、`far`，配合 `Transform3d` 使用，相机看向自身的 -Z |
| `Mesh3d` | `{ mesh: MeshId, material: MaterialId }`，一个网格加一个材质 |
| `Model3d(ModelId)` | 一个 glTF 模型。模型里的每个部件带自己的局部矩阵，画的时候乘上实体的 `Transform3d` |
| `DirectionalLight` | `direction`（光的传播方向）、`color`、`illuminance` |
| `PointLight` | `color`、`intensity`、`range`，位置取 `Transform3d` |
| `AmbientLight`（资源） | 环境光颜色 × 亮度 |
| `Assets3d`（资源） | `add_rgba` / `add_mesh` / `add_material` / `load_gltf` |

灯的数量上限：方向光 4 个、点光源 8 个（一个 uniform 装下），多出来的忽略并记一次 warn。超过上限时留下哪几盏取决于 ECS 的查询顺序，不保证稳定。

### 网格和材质

- 顶点：position / normal / uv，32 字节交错存放；索引 u32。
- 内置几何体：`Mesh::cube`、`Mesh::plane`、`Mesh::sphere`。
- 材质（glTF metallic-roughness 的子集）：`base_color`（线性 RGBA）、`base_color_texture`（sRGB）、`metallic`、`roughness`、`emissive`、`alpha_cutoff`（MASK 模式）、`double_sided`。
- 着色：Cook-Torrance（GGX 法线分布 + Smith 几何项 + Schlick 菲涅耳），环境光项是 `albedo × ambient`，不做 IBL，也不做色调映射。

### glTF

- 读 `.glb` 或内嵌 data URI 的 `.gltf`，不读外部文件（需要文件读取时放到 M5 的 `asset:/`）。
- 展开默认场景（没有就取第一个）的节点树，把层级矩阵乘到每个部件上；只认三角形图元，其他图元记 warn 跳过。
- 没有法线时按面法线计算；没有 uv 时补 0；没有索引时按顺序生成。
- 支持 base color 贴图和各项系数；法线贴图、金属度 / 粗糙度贴图、自发光贴图、采样器（一律重复平铺 + 线性过滤）、动画、蒙皮、相机和灯光扩展都不读（后续）。`BLEND` 模式按不透明处理并记 warn。
- 没指定材质的图元用 glTF 规范的默认材质（白色、metallic 1、roughness 1），不是引擎的默认材质。
- 节点必须构成树：同一个节点出现两次（成环，或被多个父节点共用）时返回错误；层级超过 256 层也返回错误。
- 加载失败（比如某个图元的索引越界）时整份文件都不收，已经加进 `Assets3d` 的贴图、网格和材质会撤掉。

## 和 2D 叠加：每帧只清一次屏

`ClearColor` 挪到 `nge-ecs`（`nge-render2d` 继续导出它），再加一个 `RenderFrame` 资源：每帧开始渲染前重置，第一个渲染器清屏，后面的叠加。渲染器的顺序就是插件添加的顺序，所以要先加 `Render3dPlugin` 再加 `Render2dPlugin`，精灵才会画在 3D 上面。

## API 形态（Rust）

```rust
fn setup(mut commands: Commands, mut assets: ResMut<Assets3d>) {
    let model = assets.load_gltf(include_bytes!("../assets/crate.glb")).unwrap();
    commands.spawn((Model3d(model), Transform3d::default(), Spin));
    commands.spawn((Camera3d::default(), Transform3d::from_xyz(0.0, 2.0, 5.0).looking_at(Vec3::ZERO, Vec3::Y)));
    commands.spawn(DirectionalLight { direction: Vec3::new(-1.0, -2.0, -1.0), ..Default::default() });
}

app.add_plugins(Render3dPlugin).add_plugins(Render2dPlugin);
```

## 验证方式

没有屏幕录制权限，画面用离屏渲染核对：测试把画面渲染到纹理、读回像素断言；验收示例的同一个场景另外输出成 PNG，人工看一眼。

## 任务拆分

1. `nge-ecs`：`ClearColor` 下沉，`RenderFrame`；2D 渲染器改成按 `RenderFrame` 清屏
2. `Transform3d` / `Camera3d` 矩阵（单测）
3. `Mesh` 和内置几何体（单测：顶点数、法线、绕序）
4. `Assets3d`、材质、灯光打包（单测）
5. glTF 加载（单测：用生成的测试模型核对部件数、层级矩阵、材质和贴图）
6. 渲染器：深度缓冲、PBR 着色器、动态 uniform（离屏测试：深度遮挡、贴图方向、方向光明暗、2D 叠加）
7. `examples/model`：带贴图的 glTF 模型旋转展示 + NSH HUD
8. 验收

## 实现和设计的差异

- **贴图按 `ImageId` 缓存 bind group**，材质本身不上 GPU：每帧按材质重新填 draw 的 uniform，所以 `Assets3d::material_mut` 改了马上生效。
- **每次 draw 一段动态 uniform**（模型矩阵、法线矩阵、材质系数），步长按设备的 `min_uniform_buffer_offset_alignment` 对齐，容量按两倍扩容。先按管线（单面 / 双面）、再按贴图排序。
- **三条管线**：背面剔除、正面剔除、双面。变换的行列式为负（镜像，比如 `scale.x = -1`）时三角形绕序反了，单面材质改用剔正面的管线，着色器判断正反面时也反过来；双面材质的背面法线在着色器里翻过来。
- **缩放为 0 的物体不画**：矩阵不可逆，没有法线矩阵。很小的缩放（比如毫米单位的模型）照常画。
- **测试模型用脚本生成**：`tools/gen_glb.py` 只用 Python 标准库，生成 `crates/nge-render3d/tests/data/test.glb`（覆盖节点层级、TRS 和矩阵两种写法、MASK、双面、缺法线、缺索引、线段图元、非默认场景）和示例用的 `examples/model/assets/crate.glb`。没有从网上下载模型。

- **原生视图让出鼠标**：`nge-platform` 的 macOS 承载视图在 `hitTest:` 返回 nil，鼠标交给外层的节点视图，`game_view` 的 `on_touch` 才收得到。之前没有这一步，Mac 上所有示例的触摸都没生效（单测是直接注入 `touch` command，所以没发现）。

## 验收记录（2026-11-04，Mac）

- **单元测试**：`nge-render3d` 26 个（相机和 `Transform3d` 5 个、网格 5 个、`Assets3d` 4 个、灯光打包 4 个、glTF 8 个：层级、几何、材质贴图、坏数据、成环和共用节点、层级过深、失败时撤掉资源、默认材质）加渲染器 1 个；`nge-ecs` 新增 `RenderFrame` 1 个；`examples/model` 3 个（拖动绕看、俯仰限位、暂停自转）。
- **离屏渲染测试** 12 个：贴图方向、两种绘制顺序下的深度遮挡、方向光明暗、点光源衰减、alpha mask、背面剔除和双面、精灵叠在 3D 上、glTF 箱子整体出图、不存在的贴图和材质退回默认、每帧都先清屏（连跑两帧）、极小缩放照常画、镜像变换后单面和双面材质都朝外。`NGE_DUMP_DIR` 设了时把箱子输出成 PNG，人工核对过：砖墙贴图、子节点的平移 / 旋转 / 缩放、光照都对。

- **iPhone**：没测（没连手机）。iOS 的承载 UIView 没加对应处理，按 UIKit 默认触摸会沿响应链往上传，要真机确认。

## 已知限制 / 后续

- 没有 mipmap：远处的贴图会闪；没有 MSAA：边缘有锯齿。
- 没有阴影、IBL、法线贴图；没有色调映射，亮度高的地方直接截断。
- `BLEND` 材质按不透明画，透明物体不排序。
- 没有环境反射：metallic 高的材质（包括 glTF 没指定材质时的默认材质）几乎只剩环境光和高光，看起来偏暗，这是符合规范的。
- 节点共用是硬错误：个别导出器会产出共用节点，别的查看器能容忍，这里整份拒收；遇到真实模型被拒再放宽。
- `load_gltf` 失败时的撤销依赖于加载和渲染在同一个线程上交替执行（现在 `App` 在渲染线程上）；以后把资源加载挪到别的线程要重新考虑。
- 2D 和 3D 的纹理各存一份 → M5 已统一到 `nge-assets`。
- TSX 场景里还不能声明 3D 节点。

## 范围外
