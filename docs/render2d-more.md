# 2D 渲染补齐：法线贴图、挡光、bloom、背景层后处理

> 前置：2D 特效（[effects2d.md](effects2d.md)）、管线预热（[pipeline-warmup.md](pipeline-warmup.md)）。

## 目标

2D 光照现在只是按距离把颜色调亮：砖墙、石头被灯照着还是平的；灯穿墙，箱子后面不会有影子；发光的东西（金币、传送门、灯）只是颜色亮一点，不会往外晕开；后处理只能整屏一起做，想只让远景糊一点、前面的角色清楚，做不到。

**验收标准**：
- 法线贴图：精灵配一张法线图，受光时按表面朝向明暗，灯从哪边来哪边亮；转动、镜像的精灵方向也对。
- 挡光：精灵或多边形挡住开了 `shadows` 的灯，后面落在阴影里；挡光的精灵自己照常被照亮。
- bloom：后处理里写 `bloom`，亮的地方往外晕开；阈值、强度、半径可调。
- 背景层后处理：后处理可以只用在背景层（z < 0），前面的精灵和 3D 不受影响。
- 平台跳跃：夜里那关的石碑有法线图、挡住角色的灯拖出影子，金币有 bloom，远山糊一点。

## 做法

### 法线贴图（`NormalMap`）

- 组件 `NormalMap(ImageId)`：一张和精灵同样排布的法线图（图集的话一格对一格，用同样的 uv）。按 OpenGL 的习惯：RGB = 法线 × 0.5 + 0.5，绿色朝上（图片的上方），蓝色朝外（朝着看的人）。
- 精灵模板新加的名字都带 `nge_` 前缀（`nge_normal_tex`、`nge_blocked` 等），不和游戏自己写的函数撞名。
- 法线图按存着的原值读：`GpuImages` 给每张 sRGB 的贴图另开一个不带 sRGB 的视图（`linear_view`，建纹理时在 `view_formats` 里加上对应的格式），PNG 和 KTX2 都一样。
- 受光、开着光照、法线图加载好了时，实例的 `flags` 带上 bit1，片元着色器：
  - 法线 = 法线图取色 × 2 − 1；按精灵的镜像（宽 / 高是负的）翻转 x / y，再转精灵的 `rotation`。
  - 每盏灯：`L = normalize(灯的位置 − 这一点, height)`，亮度再乘 `max(dot(法线, L), 0)`。环境光不受法线影响。
  - 没有法线图的精灵和以前一样（不乘这一项）。
- `Light2d.height`：灯离画面多高（point）。越低越像从侧面打过来，凹凸越明显；0 时只照朝着灯那一侧（朝外的平面几乎不亮）。`Light2d::default()` 的是 0，场景里不写时是半径的 0.25 倍。算方向时高度至少 0.001，像素正好在灯心时不出 NaN。
- 贴图组（`@group(1)`）多一个绑定：法线图；没有法线图的绑白色贴图（不读）。合批按（纹理、法线图）分，排序时同 z 同纹理的再按法线图分组。
- 法线图还没加载好时当没有法线图画（不带 bit1），不会暗一帧。

### 挡光（`Occluder2d`）

- 组件 `Occluder2d { points }`：`points` 空的时候是精灵画出来的矩形（大小、缩放、旋转、视差、插值都算上）；不空时是本地坐标的多边形（首尾自动连上），跟着 `Transform2d` 的位置、旋转、缩放走（不需要精灵）。
- `Light2d.shadows`：只有开了的灯会被挡；没开的照常穿过去（省得每盏灯都要算）。
- 每帧把挡光的边（世界坐标的线段）放进光照的 uniform：
  - 只留离某盏开了 `shadows` 的灯不到半径的边（线段到灯心的距离）；
  - 最多 `MAX_OCCLUDER_EDGES`（128）条，多了的丢掉并提示一次。
- 片元着色器：开了 `shadows` 的灯，这一点到灯心的线段和任何一条边相交时，这盏灯对这一点没有贡献。边的两端算在内（光不会从方块的角缝里漏过去），线段两头（这一点、灯心）不算。硬阴影，没有半影。
- 没写大小、贴图还没加载好的挡光精灵先不挡；带 `Repeat` 的精灵只有原来那一份挡光。
- 挡光的精灵自己不被影子盖住（实例带 bit2），否则灯在外面时它自己整个是黑的；代价是别的挡光物也挡不住照到它的光。
- 开销：每个受光的像素 × 开了 `shadows` 的灯 × 边数。灯和边都不多（几盏灯、几十条边）时没问题，文档和 TSX 的注释都写明。

### 光照的 uniform

- 每盏灯从 2 个 vec4 变成 3 个：位置、半径、强度；颜色、高度；`shadows`（0 / 1）。
- 加 `edge_count` 和 128 条边（每条一个 vec4：两个端点）。

### bloom

- 后处理里 `shader: "bloom"` 是内置的多遍效果，不是一个着色器（游戏的着色器库里不能用这个名字，用了提示一次、忽略）：
  1. 取亮部：画到半分辨率，亮度（Rec.709 的加权和）超过阈值的部分留下（按超出的比例缩放颜色，不是硬切）。按亮度而不是 RGB 的最大值：纯红的角色不会晕开，黄色的金币会。
  2. 往下缩：一级级减半，最多 `radius` 级（到 1 像素为止）。
  3. 往上放：从最小那级开始，一级级放大叠加（帐篷滤波、加法混合）回到半分辨率。
  4. 合成：原画面 + 亮部 × 强度 ÷ 级数。各级是加起来的，除以级数后，级数只改晕开的范围，不会把亮度一起叠上去。
- 参数：`x` 阈值（默认 0.8）、`y` 强度（默认 1）、`z` 级数（默认 5，1 ~ 8）。
- 中间纹理用 `Rgba16Float`（加起来不会在 1 处截断），跟着画面大小建、复用。
- bloom 可以和别的后处理按顺序排在一起，和平常一样占一遍（只是这一遍里自己分了几步）。
- 每一遍从这一帧的 uniform 池里拿一个新的 uniform（同一帧里 `write_buffer` 写同一个会互相覆盖）。
- 管线、中间纹理都按目标的格式建；后处理的链每帧预热（用不用都热）：库里的后处理在后台编，bloom 的几条管线第一次预热时就建好。背景层自己的链也每帧预热。

### 背景层后处理（`PostEffect.layer`）

- `PostEffect` 加 `layer: PostLayer`：`Screen`（默认，整屏）或 `Back`（只给 z < 0 的背景层）。
- 背景层的精灵渲染器：有 `Back` 的后处理时，先把背景画到一张离屏纹理（清成 `ClearColor`），过一遍这些后处理，最后一遍画到渲染目标上；3D 和前面的精灵照常画在上面。
- 这一层没有精灵时不做（和以前一样不开 pass）。
- 背景层不是第一个画的（前面还有别的渲染器画过）时，`Back` 的后处理跳过并提示一次。
- 和 3D 混排（`Interleave`）时本来没有背景层（所有精灵在 3D 之后按深度和模型比）；有 `Back` 的后处理时照样分出 z < 0 的那层，在 3D 之前画、过后处理，所以这些精灵总在 3D 后面。平台跳跃的远山、树都在最后面，正好。
- 背景层自己一套后处理的管线和中间纹理（和整屏的分开，uniform 不会互相覆盖）。
- 整屏的后处理只看 `Screen` 的：只有 `Back` 的时候不开整屏后处理。

### 场景和 TSX

- 精灵：
  - `normal?: string`：法线图（`asset:/` 路径或注册过的纹理名；不支持图集名，写图集时 warn、当没有）。
  - `occluder?: true | [number, number][]`：`true` 是精灵的矩形，数组是本地坐标的多边形（至少 2 个点）。
- 灯：`height?`（默认半径 × 0.25）、`shadows?: boolean`（默认 false）。
- 后处理：`layer?: "screen" | "back"`；`shader: "bloom"` 的 `params` 不写用默认值。

### 平台跳跃

- 夜里那关（第三关）起点右边两块石碑（`stonesNear`）：灰色的精灵配一张法线图（`tools/make_stone.py` 生成：四边倒角、两道横缝、表面一点起伏），挡光；角色的灯 `height` 40、开 `shadows`，走过去时石碑朝着灯的一侧亮，影子往外甩。
- 每关都有的 `POST`：整屏 `bloom`（阈值 0.6、强度 0.9）——金币、终点的绿灯附近晕开；背景层的 `blur`（5×5 取平均，`effects.ts` 里写的后处理）——远山和树糊一点，角色、平台、3D 箱子清楚。
- 夜里的 `vignette` 排在它们前面。
- `src/lib.rs` 的测试把 `blur` 也拿去校验（按 `fn post(` 认后处理）。

## 不做

- 软阴影、半影；阴影的边按像素硬切。
- 挡光物自己被别的挡光物遮住（见上面 bit2）。
- 前景层（z ≥ 0）单独的后处理：前景要画到透明的纹理上再叠回去，精灵的混合是非预乘的，边缘会发黑，以后再做。
- 粒子、文字受法线贴图影响；3D 模型被 2D 的挡光物遮住。
- 自己写多遍的后处理（bloom 是内置的）。
- 跨平台还没验证：所有 sRGB 贴图都带了 `view_formats`，Metal 上可能因此关掉无损压缩；GLES / WebGL 上视图换格式可能不生效（法线图还是会被做 sRGB 解码），做 Android、Web 时要看。
- 性能：前后两层每帧各收一遍挡光的边；所有精灵都多取一次法线图样。东西不多时不成问题。

## 验收

- `occluders` 单元测试：矩形四个角、多边形首尾连上、两个点一条边、一个点没有边；跟着位置、旋转、缩放；只留开了 `shadows` 的灯半径里的边（线段到灯心的距离），没开的灯、退化的、坏的边不要；排在 32 盏以外的灯不算；超过 128 条丢掉并返回丢了几条。
- `bloom` 单元测试：各级尺寸从半分辨率一级级减半、到 1×1 停、级数夹在 1 ~ 8、NaN 用默认的；着色器能编过。
- `effects` 单元测试：uniform 布局（3760 字节）、灯的高度和 `shadows`、边的个数；`bloom` 是保留名字、有自己的默认参数；按层取后处理。
- `batch`：同 z 同纹理按法线图分组，法线图不同就断开一批。
- `renderer`：两层按 z 分；混排时只有前面那层，有背景层后处理时照样分两层。
- `post`：只有背景层的后处理时不开整屏后处理。
- 离屏测试（有 GPU 时）：
  - 法线朝着灯的一侧按夹角亮、背着的黑；转 180°、镜像后跟着翻；朝外的法线按灯的高度算；像素正好在灯心、高度 0 时不出 NaN；法线图没加载好时和没有法线图的一样亮。
  - 挡光块后面黑、斜着擦过的不挡、灯另一边和挡光块自己照常亮；放大后的挡光块按画出来的大小挡；两个点的挡光线；没开 `shadows` 的灯穿过去，和开了的灯放在一起时照常照过来；45° 方向的光不从方块的角缝漏过去；没有尺寸的挡光精灵先不挡。
  - bloom：亮的方块旁边晕开、方块本身不变、远处暗得多、低于阈值的不晕；6 级在方块旁边不比 2 级亮。
  - 背景层后处理只改 z < 0 的；和 3D 混排时也一样；背景层和整屏都有后处理、整屏那串里 bloom 和普通的混着时每遍参数各是各的。
- 场景：法线图、挡光（`true`、多边形、不到两个点不挡）、灯的高度和 `shadows`、后处理的 `layer` 和 bloom 的默认参数；去掉就拿掉；没注册的法线图当没有。
- 平台跳跃：`effects.test.tsx` 里每关都有 bloom 和背景层的模糊、石碑带法线图和挡光、没有碰撞体、底边贴地面，角色的灯开了 `shadows`；`src/lib.rs` 校验 `blur`。
- 变异检查：两点一条边、一点没边、边跟着转、只看开影子的灯、线段距离、边数上限、退化边、边计数、灯高打包、法线乘、灯开影子、挡光物自己亮、线段不越过灯、法线镜像、法线旋转、保留 bloom、bloom 默认参数、绑定数分开、法线图没好、挡光物标记、矩形缩放、法线线性读、混排背景后处理、背景画离屏、按法线排、法线断批、阈值、合成、到 1 停、级数夹紧、级数解析、bloom 分支、整屏只看整屏、按层过滤、默认灯高、场景少于两点、场景背景层、去掉法线图、按级数归一、角不漏光、灯高下限、白色当没有、没尺寸不挡、只看前 32 盏，改掉都有测试报错。
  - 等价的一处：没有灯开 `shadows` 时也收挡光的边——`pack_edges` 反正会全丢掉，只是多算一点。
- 还没手测：石碑的凹凸和影子、bloom、远景模糊在 Mac 和 iPhone 上的样子和帧率。

## 修过的问题

- 法线图写了没注册的名字时挂上了一张白色的「法线图」（法线 (1, 1, 1)），整块变暗、偏向右上受光：现在当没有法线图。
- 背景层的后处理和 bloom 第一次用到时才编管线，切关时卡一帧：现在每帧预热，bloom 的管线预热时就建好。
- 后处理的管线有的按 `gfx.format`、有的按目标的格式建：统一按目标的格式。
- bloom 的级数调大时亮度也跟着变大：合成时除以级数。
- 灯高 0、像素正好在灯心时法线的光照方向是零向量，算出 NaN：高度至少 0.001。
- 光会从方形挡光物的两个对角之间漏过去（碰到边的端点不算挡）：边的两端算在内。
- 贴图还没加载的挡光精灵当成 1×1 的小块挡光：先不挡。
- 排在 32 盏以外（不画）的灯也让附近的边进了 uniform，占了名额：只看前 32 盏。
- 灯乘完法线项已经是 0 时还去算挡光：先跳过。
- 游戏写了叫 `bloom` 的着色器时每次场景同步都提示：只提示一次。
- 精灵模板新加的函数名可能和游戏自己写的撞：加了 `nge_` 前缀。
